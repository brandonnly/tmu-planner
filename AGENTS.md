# TMU Planner – AGENTS.md

Guidance for agentic coding tools working in this repo.
Keep changes minimal, follow existing patterns, and prefer repo tooling.

## Repo map
- `frontend/`: React + TypeScript app (Vite, TanStack Router, Tailwind/shadcn, LegendState, Supabase client)
- `supabase/`: local dev config, migrations, and seed SQL
- `scraper/`: Python 3.13 CLI scraper/uploader (Typer + Selenium + Supabase)

## Rules already in repo
- Cursor rules:
  - `.cursor/rules/project.mdc` (project overview + deployment notes)
  - `.cursor/rules/frontend.mdc` (frontend guidelines; “use bun/bunx”)
  - `.cursor/rules/backend.mdc` (scraper guidelines; mentions `backend/` but code is in `scraper/`)
- Copilot rules: none found (`.github/copilot-instructions.md` missing)

Mirrored takeaways:
- Use `bun`/`bunx` for JS commands (avoid `npm`/`npx`).
- Desktop-first UI with mobile adaptations; always ship loading/empty/error states.
- Scraper should rate-limit, retry on 429/5xx, validate/normalize before upload.

## Tooling choices
- JS package manager/runner: Bun workspaces (`package.json`, `bun.lock`)
- Frontend formatter/linter: Biome (`frontend/biome.json`: tabs, double quotes, organizeImports)
- Python environment/deps: uv (`scraper/pyproject.toml`, `scraper/uv.lock`)
- DB: Supabase CLI via npm devDependency (run with `bunx supabase ...`)

## Commands

### Setup (one-time)
```bash
# from repo root
bun install

# scraper deps
cd scraper
uv sync
```

### Frontend (Vite, port 3001)
```bash
cd frontend
bun dev
bun run build
bun run serve
bun run typecheck
```

### Lint/format (Biome)
```bash
cd frontend
bunx biome check .
bunx biome check --write .
bunx biome check --write src/routes/index.tsx
```

### Supabase (local dev)
```bash
# from repo root
bunx supabase start
bunx supabase status
bunx supabase db reset
bunx supabase stop

# migrations
bunx supabase migration new <name>
```
Ports (`supabase/config.toml`): API `54321`, DB `54322`, Studio `54323`.

Generate frontend DB types (treat as generated):
```bash
bunx supabase gen types typescript --local > frontend/src/types/database.types.ts
# or: bunx supabase gen types typescript --project-id <ref> > frontend/src/types/database.types.ts
```

### Scraper (Typer CLI)
```bash
cd scraper
uv run python cli.py --help
uv run python cli.py course <course-url>
uv run python cli.py calendar <calendar-url> --output output/courses
uv run python cli.py upload output/courses/2024_2025.json --env local
```
Note: requires Selenium + a working Chrome/driver.

## Frontend code style (TypeScript + React)
- Formatting: run Biome on touched files; avoid “style-only” diffs.
- Imports: use `@/` alias; group external → `@/` → relative; use `import type`.
- Types: `strict` enabled; avoid `any`; prefer `unknown` + narrowing; use Supabase `Database` types.
- Naming: components `PascalCase`; files `kebab-case.tsx`; LegendState observables end with `$`.
- Routing: TanStack Router file routes in `frontend/src/routes/`; each route exports `Route` via `createFileRoute`.
- Generated: never hand-edit `frontend/src/routeTree.gen.ts` (regenerated by router plugin on dev/build).
- State: LegendState updates via `.get()/.set()/.assign()/.delete()` (no in-place mutation).
- UI/CSS: Tailwind utilities; prefer shadcn/ui (`frontend/src/components/ui/`); use `cn()` from `frontend/src/lib/utils.ts`.
- UX (Cursor rule): desktop-first + mobile list-friendly layouts; touch targets on small screens.
- Error handling: user-facing messages for recoverable failures (`sonner` toasts); log context in dev; don’t swallow silently.

## Scraper code style (Python)
- Python 3.13 (`scraper/.python-version`), PEP 8, type hints, 4-space indent.
- Imports grouped stdlib → third-party → local (avoid reorder churn unless touching file).
- CLI (Typer): actionable help/error text; exit non-zero via `raise typer.Exit(1)`.
- Scraping (Cursor rule): delays/rate limiting; retry/backoff on 429 + transient 5xx; validate/normalize before saving/uploading.
- Supabase: create clients via `scraper/db/client.py:get_supabase_client`; never hardcode keys.

## Environment variables
Frontend (`frontend/src/env.d.ts`):
- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_ANON_KEY`
- `VITE_TURNSTILE_SITE_KEY`
- Optional analytics: `VITE_POSTHOG_KEY`, `VITE_POSTHOG_HOST`

Scraper (`scraper/db/client.py`):
- `SUPABASE_ENV=local|production` (default: local)
- `SUPABASE_LOCAL_URL`, `SUPABASE_LOCAL_KEY`
- `SUPABASE_PRODUCTION_URL`, `SUPABASE_PRODUCTION_KEY`

## Generated files / artifacts / secrets
- Treat as generated: `frontend/src/routeTree.gen.ts`, `frontend/src/types/database.types.ts`.
- Local-only: `supabase/.temp/` (don’t commit).
- Large artifacts: `scraper/output/` and `supabase/seed/*.sql` can be huge—avoid committing unless intentional.
- Secrets: never commit `.env*`; frontend must only use anon keys (service-role keys stay server-side/scraper).
